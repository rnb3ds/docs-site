# HTTPC

安全な HTTP クライアントライブラリ。デフォルトで安全であり、インテリジェントなリトライ、ミドルウェアチェーン、オブジェクトプール再利用を内蔵します。

HTTPC は標準ライブラリ `net/http` のトランスポート層の上に構築されています。コネクション再利用、HTTP/2 ネゴシエーション、TLS セッションなどの低層の能力は標準ライブラリと同一です。その上で、本番級の HTTP クライアントに必要でありながら標準ライブラリが提供しない機能——TLS ポリシーの強制、SSRF 防護、指数バックオフリトライ、ミドルウェアチェーン、レスポンスボディサイズの防御線、そしてオールインワンの `Result` ラッパー——を補っています。

## 特徴

- **TLS 1.2+** - 最低 TLS バージョンを強制、デフォルトは TLS 1.2-1.3
- **SSRF 防護** - デフォルトでプライベート IP 接続をブロック、CIDR 免除を設定可能
- **インテリジェントリトライ** - 指数バックオフ + ジッター、カスタムリトライ戦略に対応
- **コネクションプール管理** - 高性能なコネクション再利用、HTTP/2 対応
- **ミドルウェアチェーン** - ログ、監査、メトリクス、リカバリ、リクエスト ID などの内蔵ミドルウェア
- **ファイルダウンロード** - レジューム、プログレスコールバック、チェックサム検証に対応
- **DNS-over-HTTPS** - 内蔵 DoH リゾルバ、DNS ハイジャックリスクを低減
- **オブジェクトプール再利用** - 内部のレスポンスオブジェクトと文字列ビルダーを sync.Pool で再利用し、GC 負荷を軽減
- **プロキシとプロキシプール** - 単一プロキシ、システムプロキシ、プロキシプールのローテーション（順番/ランダム）に対応。失敗時のサーキットブレーカーとステータスコードによる IP 切り替えをサポート
- **証明書ピンニング** - SPKI ハッシュ/公開鍵ピンニング。信頼された CA が侵害されても中間者攻撃を防御
- **ドメインセッション** - DomainClient がベース URL にバインドし、SessionManager が Cookie と共通リクエストヘッダーを自動管理
- **リダイレクト制御** - 追従のオン/オフ、回数上限、宛先ドメインのホワイトリスト

## インストール

```bash
# モジュールを初期化（既存プロジェクトでは省略可）
go mod init example.com/demo

# HTTPC をインストール（Go 1.25+ が必要）
go get github.com/cybergodev/httpc
```

```go
import "github.com/cybergodev/httpc"
```

`golang.org/x/sys` 以外にサードパーティ依存はなく、インポートするだけで使用できます。初期化設定は一切不要です。

## 30 秒で体験

```go
package main

import (
    "fmt"
    "github.com/cybergodev/httpc"
)

func main() {
    result, err := httpc.Get("https://httpbin.org/get")
    if err != nil {
        panic(err)
    }

    fmt.Println(result.StatusCode()) // 200
}
```

この 1 行のリクエストの裏で何が起きているか：

1. `httpc.Get` は内部で共有のデフォルトクライアントを解決します（初回呼び出し時に遅延作成、以降は再利用、並行安全）；
2. リクエストは CRLF インジェクション防止、SSRF チェック、TLS 1.2+ ハンドシェイクを経て送信されます；
3. リトライ可能なエラー（タイムアウト、408/429/5xx など）発生時は指数バックオフで自動リトライ、最大 3 回；
4. レスポンスは `*Result` として返却されます——ステータスコード、レスポンスボディ、リトライ統計をワンストップで読み取れます。

:::tip ヒント
4xx/5xx は `error` として返却**されません**。`result.IsSuccess()` などのメソッドでステータスコードを確認してください。`err` はネットワーク層のエラーのみを表します。詳しくは [クイックスタート](./getting-started/) をご覧ください。
:::

## 標準ライブラリ net/http との関係

HTTPC の API 階層は意図的に標準ライブラリに対応しており、移行と学習コストを低減します：

- **2 層 API の対応** — パッケージレベルの `httpc.Get` は `http.Get` に（共有デフォルトインスタンス）、`httpc.New(cfg)` が返す `Client` は `http.Client` に（明示的な設定とライフサイクル）対応します。
- **トランスポート層の再造ではなく再利用** — 低層のコネクションプール、HTTP/2、プロキシトンネルは `net/http` の Transport が提供します。HTTPC はその外側にセキュリティ検証、リトライエンジン、ミドルウェアチェーン、`Result` 変換を重ねています。
- **最小インターフェース `Doer`** — `Request` メソッド 1 つだけ。実装を差し替えたい場合（テストモックなど）はこれを実装するだけでよく、完全な `Client` インターフェースに対応する必要はありません。
- **一貫したメンタルモデル** — `http.Cookie`、`context.Context`、タイムアウトのセマンティクスが標準ライブラリの使い方と 1 対 1 で対応し、既存の `net/http` 経験をそのまま移行できます。

## コアコンセプト

HTTPC は 3 つの使用方法を提供します。シンプルなものから柔軟なものまで：

```text
パッケージ関数         クライアントインスタンス            ドメインクライアント
httpc.Get()  →  client, _ := httpc.NewDefault()  →  dc, _ := httpc.NewDomainDefault(url)
一度きりのリクエスト   カスタム設定/ミドルウェア   セッション管理/Cookie 自動維持
```

### 設定プリセット

| プリセット | 適用シナリオ |
|------------|--------------|
| `DefaultConfig()` | 汎用シナリオ、安全なデフォルト値 |
| `SecureConfig()` | セキュリティ重視シナリオ、厳格なタイムアウト |
| `PerformanceConfig()` | 高スループット、大規模コネクションプール |
| `TestingConfig()` | テスト環境、セキュリティチェック無効 |
| `MinimalConfig()` | 軽量スクリプト、リトライ・リダイレクトなし |

:::tip どれを選ぶか
迷ったら `DefaultConfig()` から始めてください。ユーザー提供の URL を扱う場合は `SecureConfig()`（リダイレクト禁止、厳格なタイムアウト、5MB レスポンス上限）。高スループットには `PerformanceConfig()`（大規模コネクションプール、Cookie 有効）。ユニットテストやローカル結合テストには `TestingConfig()`（証明書検証と SSRF 防護を無効化、**本番では使用厳禁**）。一回限りのスクリプトには `MinimalConfig()`。
:::

## 本番準備完了

- **並行安全** — `Client` は複数の goroutine で共有でき、並行処理のためにクライアントを別途作る必要はありません
- **panic の安全網** — リクエスト経路上の予期しない panic は捕捉されて `error` に変換され、呼び出し側を突き抜けません
- **メモリ防御線** — レスポンスボディはデフォルトで 10MB 上限、解凍後は 100MB 上限。メモリ枯渇と解凍爆弾攻撃を防止します
- **可観測性** — ログ、メトリクス、監査、リクエスト ID ミドルウェアを内蔵。ログとエラー内の URL 認証情報、機密ヘッダーは自動マスクされます
- **明確なライフサイクル** — インスタンスクライアントは使い終わったら `Close()` でコネクションプールを解放します。パッケージ関数のデフォルトクライアントはライブラリ内部で管理され、`SetDefaultClient()` でカスタムインスタンスに置き換えることもできます
