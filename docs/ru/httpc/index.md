# HTTPC

Библиотека безопасного HTTP-клиента: безопасные настройки по умолчанию, встроенные интеллектуальные повторы, цепочка middleware и переиспользование пула объектов.

HTTPC построен поверх транспортного уровня стандартной библиотеки `net/http`: переиспользование соединений, согласование HTTP/2, TLS-сессии и другие низкоуровневые возможности идентичны стандартной библиотеке; поверх этого добавлено то, что требуется продакшен-HTTP-клиенту, но не даёт стандартная библиотека, — принудительная политика TLS, защита от SSRF, повторы с экспоненциальным откатом, цепочка middleware, лимит размера тела ответа и комплексная обёртка `Result`.

## Возможности

- **TLS 1.2+** — обязательная минимальная версия TLS, по умолчанию TLS 1.2-1.3
- **Защита от SSRF** — по умолчанию блокирует подключения к приватным IP-адресам, настраиваемые исключения CIDR
- **Интеллектуальные повторы** — экспоненциальный откат с джиттером, настраиваемая стратегия повторов
- **Управление пулом соединений** — высокопроизводительное переиспользование соединений, поддержка HTTP/2
- **Цепочка middleware** — встроенные middleware логирования, аудита, метрик, восстановления, Request ID и другие
- **Скачивание файлов** — докачка (возобновление), колбэк прогресса, проверка контрольных сумм
- **DNS-over-HTTPS** — встроенное DoH-разрешение, снижает риск перехвата DNS
- **Переиспользование пула объектов** — внутренние объекты ответов и string builder переиспользуются через sync.Pool, снижая нагрузку на GC
- **Прокси и пул прокси** — одиночный прокси, системный прокси, ротация пула (последовательная/случайная), размыкатель при сбоях и смена IP по статус-коду
- **Закрепление сертификатов** — пиннинг по SPKI-хэшу/публичному ключу защищает от MITM даже при компрометации доверенного CA
- **Доменные сессии** — DomainClient привязывает base URL, SessionManager автоматически поддерживает Cookie и общие заголовки запросов
- **Управление перенаправлениями** — переключатель следования, лимит количества и белый список целевых доменов

## Установка

```bash
# Инициализация модуля (для существующего проекта можно пропустить)
go mod init example.com/demo

# Установка HTTPC (требуется Go 1.25+)
go get github.com/cybergodev/httpc
```

```go
import "github.com/cybergodev/httpc"
```

Кроме `golang.org/x/sys` нет других сторонних зависимостей — импортируйте и используйте, никакая инициализация не требуется.

## Первый опыт за 30 секунд

```go
package main

import (
    "fmt"
    "github.com/cybergodev/httpc"
)

func main() {
    result, err := httpc.Get("https://httpbin.org/get")
    if err != nil {
        panic(err)
    }

    fmt.Println(result.StatusCode()) // 200
}
```

Что происходит за кулисами этого запроса:

1. `httpc.Get` внутри обращается к общему клиенту по умолчанию (лениво создаётся при первом вызове, затем переиспользуется, безопасен для конкурентного доступа);
2. запрос отправляется после проверок защиты от CRLF-инъекций, SSRF и TLS 1.2+-рукопожатия;
3. при повторимых ошибках (таймаут, 408/429/5xx и др.) выполняются автоматические повторы с экспоненциальным откатом, максимум 3;
4. ответ возвращается в обёртке `*Result` — код состояния, тело ответа и статистика повторов читаются из одного места.

:::tip Подсказка
Коды 4xx/5xx **не** возвращаются как `error` — проверяйте код состояния методами вроде `result.IsSuccess()`; `err` означает только ошибку сетевого уровня. Подробнее см. [Быстрый старт](./getting-started/).
:::

## Отношение к стандартной библиотеке net/http

Слои API HTTPC намеренно спроектированы в соответствии со стандартной библиотекой, снижая стоимость миграции и когнитивную нагрузку:

- **Двухслойное соответствие API** — пакетная функция `httpc.Get` соответствует `http.Get` (общий экземпляр по умолчанию); `Client`, возвращаемый `httpc.New(cfg)`, соответствует `http.Client` (явная конфигурация и жизненный цикл).
- **Переиспользование транспортного уровня вместо переизобретения** — низкоуровневый пул соединений, HTTP/2 и прокси-туннели предоставляет Transport из `net/http`; HTTPC накладывает сверху проверки безопасности, движок повторов, цепочку middleware и преобразование в `Result`.
- **Минимальный интерфейс `Doer`** — единственный метод `Request`; когда нужно подменить реализацию (например, mock в тестах), достаточно реализовать именно его, без интеграции полного интерфейса `Client`.
- **Единая ментальная модель** — `http.Cookie`, `context.Context` и семантика таймаутов соответствуют стандартной библиотеке один к одному, существующий опыт `net/http` переносится напрямую.

## Основные концепции

HTTPC предлагает три способа использования, от простого к гибкому:

```text
Функции пакета          Экземпляр клиента                    Доменный клиент
httpc.Get()  →  client, _ := httpc.NewDefault()  →  dc, _ := httpc.NewDomainDefault(url)
Разовый запрос    Пользовательская конфигурация/middleware    Управление сессией/автоподдержка Cookie
```

### Пресеты конфигурации

| Пресет | Сценарий применения |
|------|----------|
| `DefaultConfig()` | Универсальные сценарии, безопасные значения по умолчанию |
| `SecureConfig()` | Сценарии с высокими требованиями к безопасности, строгие таймауты |
| `PerformanceConfig()` | Высокая пропускная способность, большой пул соединений |
| `TestingConfig()` | Тестовая среда, проверки безопасности отключены |
| `MinimalConfig()` | Лёгкие скрипты, без повторов и перенаправлений |

:::tip Как выбрать
Если сомневаетесь — начинайте с `DefaultConfig()`; при работе с предоставленными пользователем URL используйте `SecureConfig()` (перенаправления отключены, строгие таймауты, лимит ответа 5MB); для высокой пропускной способности — `PerformanceConfig()` (большой пул соединений, Cookie включены); для модульных тестов и локальной отладки — `TestingConfig()` (проверка сертификатов и SSRF-защита отключены, **никогда не используйте в продакшене**); для одноразовых скриптов — `MinimalConfig()`.
:::

## Готовность к продакшену

- **Безопасность для конкурентного доступа** — `Client` может совместно использоваться несколькими goroutine, отдельный клиент для конкурентности не нужен
- **Страховочная сетка от паник** — неожиданные паники на пути запроса перехватываются и возвращаются как `error`, не пробивая вызывающую сторону
- **Защита памяти** — тело ответа по умолчанию ограничено 10MB, после распаковки — 100MB, что предотвращает исчерпание памяти и атаки декомпрессионными бомбами
- **Наблюдаемость** — встроенные middleware логирования, метрик, аудита и Request ID; учётные данные в URL и чувствительные заголовки автоматически маскируются в логах и ошибках
- **Понятный жизненный цикл** — экземпляр клиента после работы освобождает пул соединений вызовом `Close()`; клиент по умолчанию пакетных функций управляется внутри библиотеки, его также можно заменить собственным экземпляром через `SetDefaultClient()`
