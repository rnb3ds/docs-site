# Функции удаления

Функции удаления JSON пакета json служат для удаления узлов по указанному пути с опциональной очисткой опустевших родительских узлов. Все функции удаления **неизменяемы** — возвращается новая JSON-строка с изменениями, исходная строка остаётся нетронутой; при ошибке возвращается исходный ввод.

## Delete

Сигнатура: `func Delete(jsonStr, path string, cfg ...Config) (string, error)`

Удаляет значение по указанному пути и возвращает изменённую JSON-строку.

**Параметры**

| Имя | Тип | Обязателен | Описание |
|------|------|------|------|
| `jsonStr` | `string` | да | JSON-строка |
| `path` | `string` | да | Path-выражение (точка, индекс, подстановочный знак, срез, несколько полей) |
| `cfg` | `Config` | нет | Необязательная конфигурация (влияет на очистку и проверки) |

**Возвращаемые значения**

| Возвращаемое значение | Описание |
|--------|------|
| `result string` | Изменённая JSON-строка (при успехе); при ошибке — исходный `jsonStr` |
| `err error` | `nil` при успехе; при сбое — `*JsonsError`, оборачивающий базовую сигнатурную ошибку |

### Удаление свойства объекта

Удаляет одно вложенное свойство, возвращая новый объект без этого ключа.

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"user":{"name":"Alice","temp":"value","age":30}}`

	result, err := json.Delete(data, "user.temp")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"user":{"age":30,"name":"Alice"}}
}
```

### Удаление элемента массива

Удаляет элемент массива (индексация с 0). Элемент именно **удаляется**, а не затирается пустым значением: последующие элементы сдвигаются вперёд, индексы пересчитываются, пустот не остаётся.

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"items":["a","b","c","d"]}`

	// Удаляется элемент "b" с индексом 1, "c"/"d" автоматически сдвигаются
	result, err := json.Delete(data, "items[1]")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"items":["a","c","d"]}
}
```

Поддерживаются отрицательные индексы (отсчёт с конца, `-1` — последний):

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"items":["a","b","c","d"]}`

	// -1 указывает на последний элемент "d"
	result, err := json.Delete(data, "items[-1]")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"items":["a","b","c"]}
}
```

### Удаление по вложенному пути

Точечные пути позволяют углубляться во вложенные структуры и удалять узлы на любом уровне.

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"config":{"database":{"host":"localhost","port":5432,"password":"secret"}}}`

	result, err := json.Delete(data, "config.database.password")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"config":{"database":{"host":"localhost","port":5432}}}
}
```

### Семантика неизменяемости

`Delete` возвращает новую строку, **исходный `jsonStr` не изменяется**. Один и тот же ввод можно безопасно переиспользовать в нескольких местах:

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"a":1,"b":2,"c":3}`

	r1, _ := json.Delete(data, "a")
	r2, _ := json.Delete(data, "b")

	fmt.Println(data) // Исходные данные не изменились: {"a":1,"b":2,"c":3}
	fmt.Println(r1)   // Вывод: {"b":2,"c":3}
	fmt.Println(r2)   // Вывод: {"a":1,"c":3}
}
```

## Удаление по расширенным путям

`Delete` использует тот же рекурсивный движок путей, что и Get/Set, поддерживая подстановочные знаки, диапазоны-срезы, извлечение нескольких полей и прочую пакетную семантику. **Пакетные пути (с `*`, `{}`, `:`) устойчивы к отсутствию целей — найденное удаляется, отсутствующее молча пропускается, ошибка не возвращается**.

### Удаление по подстановочному знаку

`items[*]` удаляет все элементы массива; `[*].field` удаляет указанное свойство каждого элемента.

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"users":[{"name":"Alice","temp":"x"},{"name":"Bob","temp":"y"}]}`

	// Удаление свойства temp у каждого объекта пользователя
	result, err := json.Delete(data, "users[*].temp")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"users":[{"name":"Alice"},{"name":"Bob"}]}
}
```

Если у некоторых элементов нет целевого свойства, ошибки не будет (идемпотентная семантика, согласованная с поведением нативного `delete()` в Go для отсутствующего ключа):

<!-- check-code: skip -->
```go
// data = `[{"a":1},{"b":2}]` — у второго элемента нет a, но результат всё равно корректен
result, err := json.Delete(data, "[*].a")
// err == nil, result: [{"b":2}]
```

### Удаление по диапазону-срезу

`items[0:2]` удаляет непрерывный диапазон элементов (левая граница включается, правая исключается).

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"items":["a","b","c","d","e"]}`

	// Удаляются "a" и "b" с индексами 0 и 1 (без индекса 2)
	result, err := json.Delete(data, "items[0:2]")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: {"items":["c","d","e"]}
}
```

### Удаление с извлечением нескольких полей

`[*].{a,b}` за один раз удаляет несколько указанных свойств каждого элемента.

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `[{"name":"Alice","pwd":"x","token":"y"},{"name":"Bob","pwd":"z"}]`

	// Одновременное удаление полей pwd и token
	result, err := json.Delete(data, "[*].{pwd,token}")
	if err != nil {
		panic(err)
	}
	fmt.Println(result)
	// Вывод: [{"name":"Alice"},{"name":"Bob"}]
}
```

### Удаление по пути JSON Pointer

Если путь начинается с `/`, `Delete` разбирает его по семантике **RFC 6901 JSON Pointer** (точечный синтаксис не используется): сегменты разделяются `/`, `~0`/`~1` экранируют `~` и `/` соответственно. Это даёт способ удалять **ключи, чьи имена сами содержат точки и другие специальные символы** (точечный синтаксис такие имена выразить не может):

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	// Имя ключа "a.b" само содержит точку; точечный путь "a.b" разобьётся на два уровня и не найдёт ключ
	data := `{"a.b": 1, "user": {"name": "Alice"}}`

	r1, err := json.Delete(data, "/a.b")
	if err != nil {
		panic(err)
	}
	fmt.Println(r1) // Вывод: {"user":{"name":"Alice"}}

	// /user/name эквивалентен точечному пути user.name
	r2, err := json.Delete(data, "/user/name")
	if err != nil {
		panic(err)
	}
	fmt.Println(r2) // Вывод: {"a.b":1}
}
```

::: warning Корневой узел удалить нельзя
JSON Pointer `/` указывает на корень документа; удаление корня лишено смысла — возвращается ошибка (`cannot delete root`). Отсутствующий сегмент в указателе, как и точный точечный путь, возвращает `ErrPathNotFound`.
:::

::: tip Точный путь vs пакетный путь
- **Точный путь** (только имена свойств/индексы, например `user.temp`, `items[1]`): при отсутствии цели возвращается ошибка `ErrPathNotFound`.
- **Пакетный путь** (с `*`, `{}`, `:`, например `items[*]`, `[*].{a,b}`, `items[0:2]`): отсутствующие цели молча пропускаются без ошибки. Для строгой проверки используйте точные пути; для удаления «по возможности» — пакетные.
:::

## Обработка ошибок

Если цель точного пути не существует, `Delete` возвращает `*JsonsError`, оборачивающий `ErrPathNotFound`, причём возвращается неизменённый исходный ввод. Конкретный тип ошибки определяется через `errors.Is`:

```go
package main

import (
	"errors"
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"a":1}`

	result, err := json.Delete(data, "nonexistent.path")
	if err != nil {
		if errors.Is(err, json.ErrPathNotFound) {
			fmt.Println("Путь не существует, пропущено")
		} else {
			fmt.Println("Другая ошибка:", err)
		}
	}
	// result по-прежнему исходный JSON: {"a":1}
	fmt.Println(result)
	// Вывод:
	// Путь не существует, пропущено
	// {"a":1}
}
```

Типичные сигнатурные ошибки удаления:

| Ошибка | Сценарий срабатывания |
|------|----------|
| `ErrPathNotFound` | Не существует какой-то промежуточный сегмент точного пути либо целевой ключ/индекс |
| `ErrInvalidJSON` | `jsonStr` не является корректным JSON |
| `ErrInvalidPath` | Недействительный синтаксис path-выражения (например, незакрытая квадратная скобка) |

## DeleteClean

Сигнатура: `func DeleteClean(jsonStr, path string, cfg ...Config) (string, error)`

Удаляет указанный путь и **рекурсивно очищает** значения `null`, а также пустые объекты/массивы, возникшие после удаления. Эквивалентно `Delete(jsonStr, path, cfg)` с принудительным включением `CleanupNulls: true` + `CompactArrays: true`.

### Пример каскадной очистки

Если после удаления родительский объект опустел, `DeleteClean` дополнительно удаляет и его, каскадно поднимаясь по уровням:

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	// temp — единственное свойство user
	data := `{"user":{"temp":"value"}}`

	// Обычное удаление: user становится пустым объектом {}, но сохраняется
	r1, _ := json.Delete(data, "user.temp")
	fmt.Println(r1) // Вывод: {"user":{}}

	// DeleteClean: когда user опустел, удаляется и ключ user
	r2, err := json.DeleteClean(data, "user.temp")
	if err != nil {
		panic(err)
	}
	fmt.Println(r2) // Вывод: {}
}
```

### Очистка временных полей в ответе API

`DeleteClean` удобен для зачистки ответов API: удаляет целевое поле и заодно выметает другие `null` и остаточные пустые контейнеры, не показывая фронту «пустые оболочки»:

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	apiResp := `{"data":{"id":1,"name":"Product","desc":null,"price":29.99,"note":null}}`

	// Один DeleteClean удаляет desc и выметает другие null (note) по всему дереву
	cleaned, err := json.DeleteClean(apiResp, "data.desc")
	if err != nil {
		panic(err)
	}
	fmt.Println(cleaned)
	// Вывод: {"data":{"id":1,"name":"Product","price":29.99}}
}
```

::: warning DeleteClean выметает null по всему дереву
Очистка в `DeleteClean` **глобальна**: она рекурсивно очищает всё JSON-дерево, поэтому удаляются **все** предварительно существовавшие `null` и пустые контейнеры, а не только возникшие в точке удаления. Если нужно удалить только указанное поле, сохранив остальные `null`, используйте обычный `Delete`.
:::

## Связь DeleteClean с Config

`DeleteClean` по сути — синтаксический сахар над `Delete` + двумя параметрами конфигурации. Можно явно передать ту же конфигурацию обычному `Delete` — результат полностью эквивалентен:

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"user":{"temp":"value"}}`

	// Способ 1: DeleteClean
	r1, _ := json.DeleteClean(data, "user.temp")

	// Способ 2: Delete + явная конфигурация (полностью эквивалентно)
	cfg := json.DefaultConfig()
	cfg.CleanupNulls = true
	cfg.CompactArrays = true
	r2, _ := json.Delete(data, "user.temp", cfg)

	fmt.Println(r1) // Вывод: {}
	fmt.Println(r2) // Вывод: {}
}
```

Поля `Config`, влияющие на удаление:

| Поле | По умолчанию | Влияние на удаление |
|------|------|--------------|
| `CleanupNulls` | `false` | Рекурсивно удаляет `null` и пустые объекты/массивы из результата (каскадная очистка) |
| `CompactArrays` | `false` | Удаляет `null`/пустые элементы из массивов; при включении подразумевает `CleanupNulls` |
| `CreatePaths` | `true` | **Не влияет на удаление** (удаление никогда не создаёт пути; указано для сравнения) |

## Сравнение Delete и DeleteClean

| Свойство | Delete | DeleteClean |
|------|--------|-------------|
| Удаление целевого узла | да | да |
| Пересчёт индексов после удаления элемента массива (без пустот) | да | да |
| Ошибка при отсутствии точного пути | да (`ErrPathNotFound`) | да (`ErrPathNotFound`) |
| Очистка `null`, возникших при удалении | нет | да |
| Очистка пустых объектов/массивов (каскад) | нет | да (по уровням вверх) |
| Выметание предварительно существовавших `null` по всему дереву | нет | да (глобальная очистка) |
| Эквивалентная конфигурация | по умолчанию | `CleanupNulls+CompactArrays` |
| Относительные затраты | ниже | несколько выше (дополнительный обход дерева для очистки) |

## Распространённые подводные камни

::: warning Удаление из массива не оставляет пустот
При удалении элемента массива `Delete` **полностью удаляет** его, сдвигая последующие элементы вперёд, — плейсхолдеров `null` и пустот не остаётся. Если ожидается, что индексы после удаления сохранятся (с пустыми позициями), семантика удаления CyberGo этого не предусматривает — задайте в этой позиции `null` через `Set`.
:::

::: warning DeleteClean может случайно удалить корректные данные, «случайно пустые»
Каскадная очистка `DeleteClean` рассматривает все пустые объекты `{}` и пустые массивы `[]` как подлежащие удалению. Если в вашей бизнес-семантике «пустой массив» или «пустой объект» — значимое состояние (например, `"tags":[]` означает «нет тегов», а не «поле отсутствует»), `DeleteClean` удалит их вместе с ключом. Чтобы сохранить такие поля, используйте обычный `Delete`.
:::

::: warning Пакетное удаление устойчиво к отсутствию
Пути с подстановочными знаками/срезами/несколькими полями **молча пропускают** отсутствующие цели, не возвращая ошибку. Если нужна строгая семантика «цель обязана существовать», используйте точные пути (например, `items[1]` вместо `items[*]`).
:::

## Пакетное удаление нескольких полей

Чтобы удалить за один приём несколько несвязанных полей, достаточно вызвать обычный `Delete` в цикле (каждый раз на основе предыдущего результата):

```go
package main

import (
	"fmt"

	"github.com/cybergodev/json"
)

func main() {
	data := `{"user":{"id":1,"name":"Alice","password":"secret","ssn":"123-45-6789"}}`

	sensitive := []string{"user.password", "user.ssn"}
	result := data
	for _, field := range sensitive {
		var err error
		result, err = json.Delete(result, field)
		if err != nil {
			fmt.Printf("Не удалось удалить %s: %v\n", field, err)
		}
	}
	fmt.Println(result)
	// Вывод: {"user":{"id":1,"name":"Alice"}}
}
```
